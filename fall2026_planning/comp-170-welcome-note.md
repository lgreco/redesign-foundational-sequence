How Are My Courses Changing
Our profession, and our discipline, is changing quickly, and so are my courses. This is no longer just a course on a computing discipline — it's a course on how to leverage AI within that discipline, and how to learn with and from it. For example: how can AI make you a better junior programmer (COMP 170)? How can AI help you fine-tune solutions using classic and emerging data structures (COMP 271)? How does AI sharpen problem analysis and program performance tuning (COMP 363)?

Don't worry — we'll still cover the fundamentals of each course: the math, logic, physics, and electronics of computing; the history of computing; and so on. Along the way, we'll also explore how to write operational prompts for AI, how to write skill files, and how to build model context protocol tools for agents.

A New Approach to Assignments
To prepare for the challenges and opportunities AI brings, I'm trying something new this term: some work will still happen at home, but a lot of the assignments will be done in class. That frees up some of your time to actually read about the course, and gives you a supportive environment to work through assignments in.

Class Recordings
You'll see me wearing a wireless microphone during class. I record audio, then use an agent to transcribe it and convert it into a summary of the class meeting, which I share with you afterward. The agent is instructed to transcribe only my voice, and to isolate and omit any audio of students.

My Use of AI
Everything I produce for this course — class notes, slides, code — is my own work. I do use AI agents for text editing (catching typos, grammar, syntax) and to improve code documentation (specifically, reformatting my comment blocks and improving their clarity).

For any student-facing use of AI, I publish my prompts so you can review them and understand how I use AI to, hopefully, improve your learning experience. If you have questions, suggestions, or concerns, I'm happy to discuss them.

Advice for Succeeding in the Course
Read.

Reading is the one skill that can make you resilient to AI and shield your career from automation. Read intensely, intently, with focus. Reread, with purpose. Process what you read, and make sure you get it. Read everything in its entirety — emails, comments in code, class notes, newsletters I publish, GitHub documents. Read it all. Spend time reading; don't browse.

The biggest technological accomplishment of the 21st century so far is built on reading — that's how frontier models like Claude's Fable learn. To compete with them, you have to read well. You can do it, but you have to dedicate time to reading with purpose and without distractions.

Take notes.

Writing is a pivotal mechanism for learning — this is science: graphomotor skills and practice contribute to human learning (see also this peer-reviewed study on graphomotor skills: https://pmc.ncbi.nlm.nih.gov/articles/PMC11943480/). Typing on a keyboard is not writing. Take down notes in class, and write notes while you're reading.

Understand how grading works ("ungrading").

There are no traditional numeric grades on individual assignments; each earns 1 point simply for completion. You propose your own letter grade at midterm and at term-end, from this scale:

A: you learned from your mistakes and didn't repeat them; missed 5 or fewer class meetings; participated in class (answered questions, joined conversations, offered suggestions); reached out to me about assignments, by email or during student hours; missed no more than 2 assignments.
C+: your code was flawless, but you missed 6 or 7 class meetings and didn't participate in class or come to student hours.
D: you kept repeating the same mistakes; missed 8 or 9 class meetings; missed exactly 3 assignments.
F: missed 10 or more class meetings; missed 4 or more assignments; or violated the university's or the course's academic integrity policy.
"Missed" class meetings in this scale means any absence not excused under the university's official definition above.

Take deadlines seriously.

Late homework is not accepted. Missing 3 assignments puts you in D-range; missing 4 or more fails the course. Start each assignment within 24 hours of it being posted, so problems surface while there's still time to get help.

Uphold academic integrity.

You're encouraged to research online (e.g., GeeksforGeeks, Stack Overflow) and use AI tools, but you must understand and be able to explain anything you use. Cite any generative AI tool use, including the specific prompts you used. Don't copy verbatim — internalize borrowed solutions in your own words.

Be cool like a pro.

Use professional email conventions: a greeting, a clear objective, and a closing (avoid "hey"). Attach program files when asking for help troubleshooting code, not screenshots or cloud links. Name files meaningfully (e.g., "JohnDoe_problem1a.py", not "mycode.py"). Follow instructions carefully and submit organized, legible work.

Ask for help the right way.

Spend some real time (20–40 minutes) attempting a problem before requesting help. If you can't finish an assignment, show your pseudocode or partial attempt rather than nothing. Book student hours in advance (e.g., via Calendly) — walk-ins are welcome, but appointments are prioritized. Come prepared: laptop charged, code loaded, ready to work.

Manage your time.

There are spectacular tools available to you, many at no cost. Start with Outlook Calendar (or Google Calendar) and explore your options from there. A well-organized schedule is an essential soft/life skill.
